Why it looks like this

Short notes on each choice. The first one changes with the situation.

Cards, and why

Recommended: one card per goal. Each card holds a goal's name, its progress line, and the agents building it right now. So one box answers three questions together: what is being built, how far it has got, and who is on it. That is what makes it an overview rather than two lists you have to match up by eye.

Every box groups something real: a goal and its crew. Agents with no work are not boxed; they sit in a plain list after the cards (or in the empty grid cell when the cards leave one). No box sits inside another; the card has no border in dark and a hairline in light.

Rows (the switch) keeps v2's fixed-order agent list and puts each goal's line beside its name. It's calmer and scans better past 15 agents, but you have to connect agents to goals yourself. Cost of Cards: an agent moves to another card when its work moves to another goal. That move is the news, so I think it's worth it.

Focal point and the first five seconds

0–1 s: a waiting question, if there is one: first on the page and the only amber. 1–2 s: the heading, 44 px and the largest thing by far (30 px on a phone). 2–4 s: the green lines: how far each goal has got. 4–5 s: the rings: who is moving.

Squint test: the heading is the one dark mass, the green lines are the one colour mass. Nothing else competes.

Progress, drawn honestly

Goals: one segment per ticket, so "4 of 7 done" is literally four of seven pieces. done being built now its agent stopped not started. The count is always beside the line, in text, so it's never colour alone. Over 16 tickets the segments merge into one continuous line.

Agents: the record has the agent's planned steps (ticket_steps), not how much of the work is done. So an agent shows "step 3 of 5" as short bars, one per step, and never a percentage. Steps can be re-planned, so the bars show where it is, not how long is left. An agent with no planned steps (Captain while it reviews) shows no bars; its breathing ring alone says it's working.

The ring breathes only while the agent's runner is reporting; when that stops, the ring goes still and the word changes.

Character: what makes it AutoKolab

The croc green means done. The logo's green (#5DC46A) is used for one thing: finished work in the progress lines. So the brand colour grows on the page as the project gets done. In light theme, done segments get the croc's dark ink outline, drawn like the logo.

The lines are the croc's back. Rounded segments with small gaps, like the bumps along its spine, instead of a generic smooth bar.

The croc turns up when there's nothing to report. Tilted and resting when it's calm, larger and looking toward "Tell Captain" when the project is new. Never on loading or errors: a failure isn't cute.

Presence, not dots. Each agent is a neutral tile with a ring in its status colour; working ones breathe slowly, staggered so they don't pulse in step.

Numbers in Geist Mono, like a build log. Big confident type for the one sentence that matters, and everything else much smaller.

What's loud, what's quiet

Loud: the heading; the waiting question; "has stopped" in coral in the heading. Middle: goal names and their lines. Quiet: section titles (sentence case, with a hairline), step bars, idle agents (outlined tiles, grey words, no ring).

Colour only means status: green done, blue working, amber needs you, coral stopped. Every colour has a word next to it. Avatars stay neutral.

Same elements as v2, plus lines

Needs you (only when waiting, a small amber mark, no box), the heading with the "has stopped" clause, every agent with what it is building or Idle, and the goals being built. Progress lines are the only new thing.

Not here: Next from Captain, delivered list, freshness label, count tiles, calm footer.

Phone, keyboard, motion

Phone: same order, cards stack, an agent row becomes three short lines (name and state; what it's doing; steps). Every target is 44 px or more. Each card header and each agent row is one link and one Tab stop; the card itself is not a link, so there are no links inside links.

Motion is only the ring breathing and a 160 ms hover fade. Under reduced motion both stop; the rings stay as still rings. Use "Reduce motion" above to see it.

Where this goes against the handoff

Progress lines: v2 and my spec said "no bar". The ticket reverses that; this follows the ticket.

Done colour: tokens.css has --green #5CCB9A for done. This uses the logo's #5DC46A so the brand and "done" are one colour. If kept, the token should change.

Light theme is a proposal; tokens.css has none. Focus ring uses --text-muted, as in v2, because --border-focus is under 3:1.
