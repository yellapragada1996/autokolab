#SituationHeading, as code builds it

How code picks the sentence

  • Setting up comes first: nothing connected, then only Captain, then agents but no goal. Each is two sentences: what is true, then the one next step as a link.
  • Paused replaces everything else: "You paused everyone." (or "Raghav paused everyone." for a member).
  • Working: Captain counts while it reviews. One agent is named ("Birch is working on Checkout."); more are counted ("3 agents are working on…"). One goal is named, two if their names fit in 32 characters together, otherwise counted ("on 2 goals").
  • Nobody working: "No agents are working right now.", after "All 3 goals are done." when every goal is done.
  • Then, one line each, in this order: who has stopped (coral), who is offline with work waiting, Captain offline, goals finished today, and "Tell Captain what you want to make." for someone who has never written to Captain.
  • Never in the heading: what waits on you. Needs you, right above, already says it.

Rules this page follows

The same rules in every situation. If a frame above breaks one, that's a bug.

What stands out

  • One thing first. If something waits on you, Needs you is first: top of the page, the only filled amber. Otherwise the heading is first: 44 px, the largest thing on the page.
  • Then the lines, then the rings. Everything else is grey text.
  • Empty parts are not drawn. No Needs you when nothing waits on you, no cards when nothing is being built, no "Not working right now" when everyone has work, no Captain count when it's zero. Nothing leaves a gap or an empty box.
  • No problem blocks. A failure shows in three places that already exist: one line in the heading, the agent's row (word and reason) and its ticket's segment.
  • Nothing is answered here (DEC-24). Every Needs you row is a link to the exact message in Captain. Someone who can't answer sees it quietly, with a link to the ticket in Work.

Colours and what they mean

Colour only means status, and every colour has a word next to it. Avatars are neutral.

Green, solid: done.
Blue, striped: in progress (an agent is building it or Captain is reviewing it). A blue ring: that agent is working.
Amber, striped: waiting on a person (you, or the person named). A filled amber mark: it needs you. A hollow one: it needs someone else.
Coral, broken: stopped (an error, failing tests it gave up on, or a daily limit).
Outline: to go. Nobody has started it.
WGrey, no ring: idle, offline or paused. The word says which.

Motion

  • Only working agents move: their ring breathes slowly (3.2 s). Nothing else animates.
  • When nothing on screen is live, nothing breathes: paused, and after a failed refresh (the view is old).
  • Nothing jumps: loading shows the cards' real shapes, which don't shimmer. A new question adds a row at the top; that's the news.
  • Reduce motion (system setting, or the switch at the top) stops the breathing. The rings stay.

Contrast (worked out from the colours in use)

Against its backgroundDarkLight

Text needs 4.5:1, lines and rings 3:1. *In light, the done segment passes through its ink outline. Same as v4.

Where this goes against the handoff or the spec

  • Same as v4: the done green is the logo's #5DC46A; light theme is a proposal; the focus ring uses --text-muted; progress lines replace the spec's "4 of 7 done".
  • Needs you shows 3 rows, as the spec says, then "and N more in Captain". v4 showed 2.
  • A finished goal stays for the rest of the day. The spec drops it at the next refresh, so whoever looks later would never see it finish.
  • One agent is named in the heading ("Birch is working on Checkout."), as the spec says. v4 never drew one agent.
